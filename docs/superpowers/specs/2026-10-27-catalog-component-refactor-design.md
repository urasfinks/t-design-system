# Полный рефакторинг компонентов и демо-каталога TDS

## Намерение

Исправить все подтверждённые проблемы аудита и превратить каталог из длинной витрины в быстрый справочник. Одновременно устранить архитектурное смешение в `catalog.js`, не меняя публичный API дизайн-системы и не превращая документацию в SPA.

Пользователи должны быстро находить компонент или токен, различать все состояния контролов, сравнивать числовые значения и получать одинаковое поведение во всех трёх темах, с клавиатуры и на узком экране.

## Цели

- Видимые границы невыбранных checkbox/radio во всех темах и при increased contrast.
- Семантический цвет placeholder у `.tg-search__input` с контрастом не ниже 4.5:1.
- Глобальный поиск по разделам, компонентам, классам и токенам с `/` и Cmd/Ctrl+K.
- Сгруппированная desktop- и mobile-навигация по каталогу.
- Публичная числовая типографика для таблиц, списков и денежных значений.
- Compositor-friendly motion и единые duration/disabled tokens.
- Мобильная палитра без дробления имён токенов.
- Модульная организация поведения каталога со статической семантической разметкой примеров.
- Task-focused заголовки и более сдержанная пунктуация.
- Актуальный visual baseline и проверки новых контрактов.

## Не входит

- Новый визуальный мир, rebranding или смена четырёх исходных цветов тем.
- SPA, client-side routing, фреймворк, bundler или новые runtime-зависимости.
- Генерация всей документации через `innerHTML`.
- Удаление или переименование существующих публичных `.tg-*` классов.
- Изменение бизнес-логики живых демонстраций.
- Полный редизайн отдельных `compositions.html`, `bottom-panel.html` и `icon-browser.html`.

## Ограничения

- Нативный HTML прежде custom widget; CSS работает без JS.
- Примеры остаются в `docs/index.html`, чтобы читаться и отображаться без скриптов.
- Общие стили компонентов остаются в их SCSS-владельцах и слое `tds.components`.
- Каталог использует роли и геометрию TDS, не создаёт альтернативную палитру.
- Touch-цели не меньше 44px, видимый focus, reduced-motion и forced-colors сохраняются.
- 320–1440px, 200% text, Light/Desktop Dark/iOS Dark, Chromium и WebKit там, где набор это поддерживает.
- Существующие несвязанные изменения пользователя в `.gitignore`, `skills-lock.json` и installed skills не перезаписываются.

## Подходы

### 1. Точечный

Исправить CSS и добавить поиск в существующий монолит `catalog.js`. Минимальный diff, но навигация, демо-состояния и генерация code previews остаются связанными. Не выбран.

### 2. Полный модульный — выбран

Сохранить статический HTML и разделить JS по ответственности. Добавить нативный search dialog и сгруппированную навигацию без фреймворка. Даёт проверяемые модули и сохраняет прогрессивное улучшение.

### 3. Полностью data-driven каталог

Генерировать секции и примеры из JS-данных. Уменьшил бы повторяющуюся разметку, но ухудшил бы доступность без JS, читаемость источника и объём регрессии. Отклонён.

## Архитектура каталога

### JavaScript

- `catalog.js` — тонкая composition root: импортирует и инициализирует модули, не содержит отдельные demo-handlers.
- `catalog-navigation.js` — hash navigation, mobile select, IntersectionObserver, активный пункт и scroll sync.
- `catalog-search.js` — индекс, dialog, фильтрация, keyboard shortcuts, выбор результата и live status.
- `catalog-demos.js` — theme/accent, tabs, toast, dialog demo, snackbar, upload, pagination, range, transition и refresh.
- `demo-code.js` — формирование disclosures с исходным HTML примеров.
- `icon-browser.js` остаётся самостоятельным владельцем галереи иконок.

Модули получают необходимые DOM-элементы или root через параметры и экспортируют функции инициализации. Не вводится глобальное состояние, кроме существующего `document.documentElement` для темы и акцента.

### Поиск

- Один `<dialog>` с явным label, `input[type=search]`, списком результатов и пустым состоянием.
- Индекс строится из статических секций и явных `data-search-*` метаданных; не скрапит весь visible text и не индексирует code previews.
- Результаты ведут на существующие id. Для точного поиска токенов секция палитры получает отдельные searchable aliases без создания ложных anchor-элементов.
- Поиск по подстроке без учёта регистра, с нормализацией пробелов; русские названия, классы и токены равноправны.
- `/` и Cmd/Ctrl+K открывают dialog, если фокус не в editable-поле и нет активного modal/dialog.
- Native Escape закрывает dialog и возвращает фокус; ArrowUp/ArrowDown перемещаются по результатам, Enter открывает выбранный результат.
- После выбора dialog закрывается, hash обновляется, цель получает корректный scroll/focus без потери позиции чтения.
- Счётчик/пустой результат объявляются через `aria-live`; нет результатов не считается ошибкой.

### Навигация и структура

- Desktop sidebar получает группы: «Обзор», «Основа», «Компоненты», «Паттерны», «Подключение».
- Те же группы отражаются через `optgroup` в mobile select.
- Рядом с навигацией доступна кнопка поиска с текстовым label и keyboard hint на desktop.
- Текущие 14 разделов и их id сохраняются для совместимости ссылок и тестов.
- Поэтичные H2 заменяются ясными названиями задач; короткие пояснения остаются.
- Hero сохраняется, но не становится препятствием для поиска: глобальный поиск доступен из постоянной навигации.

## Компонентные изменения

### Choice controls

- Добавить семантический `--choice-border-color`, производный от существующих нейтральных ролей, без нового цвета палитры.
- Убрать transparent border у unchecked `.tg-check`/`.tg-radio`.
- Обеспечить контраст границы не ниже 3:1 к соседнему фону во всех темах.
- Checked/indeterminate состояния остаются акцентными; forced-colors продолжает использовать native appearance.
- Обновить `DESIGN.md`, `field-focus` и связанные assertions, чтобы контракт не закреплял старое невидимое состояние.

### Search placeholder

- `.tg-search__input::placeholder` использует `var(--text-secondary)` и `opacity: 1`.
- Browser-тест измеряет фактический placeholder contrast во всех темах и на фоне wrapper, а не только цвет обычного input.

### Числовая типографика

- Добавить публичные `.tg-num` и `.tg-table__num`: `font-variant-numeric: tabular-nums`, `text-align: end`.
- Применить к суммам, количествам и соответствующим заголовкам в примерах; текстовые ячейки остаются start-aligned.
- Денежные значения списков используют `.tg-num`, без изменения их semantic HTML.

### Motion

- Custom progress bar анимируется через `transform: scaleX()`; исходный размер и clipping сохраняются, transform-origin учитывает inline direction.
- Native progress pseudo-elements остаются совместимыми: если transform нельзя применить без потери нативной модели, используется минимальный безопасный вариант и отдельный тест, без одинакового хак-решения для всех браузеров.
- Switch knob перемещается через transform с существующим вертикальным центрированием и RTL-поведением.
- `.tg-fade-in`/`.tg-fade-out` используют `var(--duration)` и `var(--ease)`.
- Search dialog получает короткое появление/исчезновение через opacity и небольшой scale/translate, backdrop затухает отдельно; native Escape и focus return не задерживаются ради анимации.
- Активные пункты навигации и результаты поиска используют спокойные color/background transitions без движения layout.
- Toast, snackbar, tabs, disclosures и существующие demo transitions приводятся к общим duration/easing там, где уже есть motion; новые декоративные циклы не добавляются.
- Hover/press остаются сдержанными и используют общий control-state engine; parallax, постоянно движущиеся украшения и animated gradient background не вводятся.
- Reduced-motion отключает необязательные переходы и появления; функциональные spinner/stripes не меняются без необходимости.

### Disabled

- Ввести общий `--disabled-opacity` в tokens с единым значением, заменить hardcoded `.45`/`.5` там, где это часть общего disabled-контракта.
- Не повышать контраст через случайные отдельные цвета и не объявлять disabled обычным WCAG text-contrast случаем.
- Сохранить читаемость labels и disabled semantics; визуально сравнить Light/Dark/iOS Dark.

### Акцент и палитра

- Каталог меняет только `--button-color` и необходимый foreground; derived link/accent aliases наследуются из tokens.
- Убрать лишние overrides `--link-color` и `--accent-text-color` из каталога и соответствующих тестов.
- Mobile palette вместо четырёх сжатых колонок показывает карточки/строки с полным именем токена, ролью и swatch.
- Использовать семантическую разметку списка на узком экране или доступное CSS-представление таблицы, не дублируя расходящиеся данные вручную.

## Baseline и документация

- Обновить `DESIGN.md`: choice border, numeric utility, disabled/motion tokens и структуру readable palette остаются явными.
- Обновить `docs/component-standard.md`, если добавляется новый публичный класс или контракт.
- Обновить README для `.tg-num`/`.tg-table__num` и новых tokens, если они входят в публичный CSS API.
- Переснять `tests/fixtures/cascade-baseline/t-design-system.css` и `catalog.css` только после визуального review, чтобы baseline соответствовал намеренным изменениям.
- Не подгонять assertions под код: сначала тест нового требования, затем реализация; baseline обновляется как отдельное намеренное действие.

## Проверка

### Сначала failing tests

- Choice border contrast ≥3:1 во всех темах.
- Search placeholder contrast ≥4.5:1 во всех темах.
- `.tg-num`/`.tg-table__num`: tabular numerals и правильное выравнивание.
- Disabled controls используют один token.
- Motion использует заданные transform/duration contracts и не ломает RTL/reduced-motion.
- Глобальный поиск: открытие кнопкой, `/`, Cmd/Ctrl+K, фильтрация по названию/class/token, arrows, Enter, Escape, empty state, focus return и mobile.
- Навигация: группы/optgroup, текущий раздел, повторный выбор того же hash.
- Mobile palette: полные имена токенов, отсутствие overflow и дублированных несинхронных данных.
- Каталог продолжает показывать исходный HTML примеров без исполнения их копий.

### Финальная матрица

- `npm test` и полный `npm run test:browser`.
- Дополнительный WebKit-набор существующего runner, если предусмотрен проектом.
- Build, independent SCSS imports, lint и taste inspector без необоснованного подавления findings.
- Ручной браузерный осмотр 320, 390, 768 и 1440px; Light/Desktop Dark/iOS Dark.
- Keyboard-only, 200% text, reduced-motion, forced-colors, длинные запросы и пустой поиск.
- Скриншоты до/после ключевых областей: sidebar/search, forms, palette, tables и mobile navigation.

## Критерий приёмки

Все пункты аудита закрыты, каталог работает как searchable reference, примеры остаются статическими и доступными, публичные классы сохранены, полный тестовый набор проходит без скрытых исключений, а визуальные изменения подтверждены скриншотами во всех темах и целевых размерах.
