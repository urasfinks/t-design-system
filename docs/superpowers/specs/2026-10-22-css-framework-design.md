# t-design-system: дизайн первой версии

Дата: 22 октября 2026 года.
Статус: состав согласован в чате; документ подготовлен для проверки пользователем.

## Назначение и границы

Выделить визуальную систему проекта `/Users/urasfinks/WebStormProjects/ai-splitter-ng`
в самостоятельный CSS-фреймворк в текущем репозитории `t-design-system`.
Фреймворк работает в обычном HTML, Angular и Telegram Mini Apps.
Исходный проект используется как источник и не изменяется.

Первая версия включает CSS, модульные SCSS-исходники, документацию и локальную
витрину компонентов. Публикация в npm, Angular-компоненты и подключение пакета
к исходному приложению не входят в эту версию.

## Выбранный подход

Модульные SCSS-исходники компилируются в готовый CSS без зависимостей во время
выполнения. Это сохраняет возможность подключения одним файлом и выборочного
использования модулей в проектах со сборкой.

Рассмотренные альтернативы: единый вручную поддерживаемый CSS проще начать,
но сложнее сопровождать; Angular-библиотека могла бы включать поведение,
но ограничила бы применение фреймворка. Выбран самостоятельный CSS-пакет.

## Визуальный контракт

Источник — `src/styles.scss` и общие компоненты исходного приложения.
Сохраняются пропорции, rem-размеры, fluid-типографика, скругления, поверхности
и основные классы `.tg-*`, включая существующие BEM-модификаторы.
Префикс является историческим именем API и не требует Telegram.

При переносе удаляются закомментированные эксперименты и дубли, исправляются
ошибки синтаксиса, добавляются состояния focus-visible и disabled.
Проектные ID, стили разделения счёта, Angular-селекторы `:host`, CDK-overlay
и служебные стили конкретных экранов не входят в общее ядро.
Универсальные стили прогресса и аватаров получают имена `.tg-*`.
Полная совместимость со всеми непредфиксированными классами приложения
не обещается; README перечисляет перенесённые публичные классы.

## Темы и токены

Публичные токены сохраняют существующие имена: `--bg-color`, `--text-color`,
`--button-color`, `--space-1`–`--space-5`, `--radius`, `--control-h`, `--fs`
и остальные используемые общими компонентами переменные.
У каждого используемого токена есть определение или резервное значение.

По умолчанию действует самостоятельная светлая тема. Тёмная тема выбирается
системным `prefers-color-scheme`, когда нет явного выбора. Атрибут
`data-theme="light"` или `data-theme="dark"` на корневом элементе позволяет
явно выбрать тему. Пользователь может переопределять токены своим CSS.

Отдельный файл `telegram.css`, подключённый после основного, связывает цвета
с официальными CSS-переменными Telegram `--tg-theme-*`, с резервными значениями
для запуска вне Telegram. SDK отвечает за обновление переменных, адаптер —
только за отображение цветов. Старые `--tg-*` переменные исходного проекта
учитываются как дополнительный источник, когда официальные отсутствуют.
Обычная тема не должна зависеть от наличия SDK.

## Модули и компоненты

- Основа: токены, темы, базовая типографика и box-sizing.
- Компоновка: контейнеры, секции, строки, колонки, отступы и разделители.
- Поверхности: карточки, заголовки, списки и строки списка.
- Управление: кнопки, кнопки с иконками, input, select, textarea, подписи,
  переключатели и чипы.
- Навигация: табы и нижняя панель с учётом safe area.
- Обратная связь: аватары, бейджи, прогресс, уведомления, toast и модальные окна.
- Доступность: заметный фокус, disabled, уменьшение анимации по настройке ОС.

Интерактивные компоненты предоставляют внешний вид и контракт разметки.
Приложение управляет состоянием через нативные атрибуты, ARIA и классы.
CSS не реализует обработчики, удержание фокуса, переключение табов или
объявление уведомлений скринридером. Для модального примера предпочтителен
нативный `dialog`; документация объясняет открытие и закрытие через приложение.
Примеры переключателей и табов используют корректную семантику и клавиатуру.

## Структура и артефакты

```text
src/
  tokens/           # размеры и семантические цвета
  themes/           # светлая, тёмная, адаптер Telegram
  base/             # базовые стили
  components/       # отдельные компоненты
  utilities/        # компоновка и служебные классы
  index.scss        # основной вход
  telegram.scss     # отдельный вход адаптера
dist/
  t-design-system.css
  t-design-system.min.css
  telegram.css
  telegram.min.css
docs/
  index.html        # локальная витрина и примеры
README.md           # установка, темы, классы и интеграция
package.json        # метаданные, exports и команды сборки
```

Сборка выполняется одной npm-командой и создаёт обычные и минифицированные
файлы из SCSS. В пакет входят dist и необходимые SCSS-исходники.
Название пакета — `t-design-system`, начальная версия — `0.1.0`;
доступность имени в реестре не предполагается и для локальной версии не нужна.
Лицензия оригинального приложения не установлена: новую лицензию и заявления
о правах автоматически не добавлять.

Витрина показывает все компоненты, код разметки, варианты и состояния,
переключение тем и пример переопределения токенов. Её JavaScript служит
демонстрации и не является частью CSS-пакета.

## Проверка результата

1. Чистая сборка SCSS создаёт четыре заявленных файла без ошибок.
2. Проверка упаковываемых файлов подтверждает наличие CSS и SCSS-входов.
3. Браузерная проверка витрины на мобильной и настольной ширине подтверждает
   отсутствие горизонтального переполнения и читаемость компонентов.
4. Светлая, тёмная и явно выбранная темы работают вне Telegram; тестовые
   `--tg-theme-*` переменные изменяют цвета при подключении адаптера.
5. Проверяются клавиатурный фокус, disabled и reduced-motion, длинные подписи,
   а также примеры состояний табов, switch, toast, progress и dialog.
6. Проверяется, что проект-источник не изменён в ходе работы.

Перед реализацией конкретные имена новых классов и список сохраняемых классов
фиксируются в плане по результатам полного разбора исходных стилей.
