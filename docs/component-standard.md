# Стандарт компонента TDS

README определяет публичный контракт системы. DESIGN.md уточняет визуальные решения.
Этот документ задаёт критерии для новых компонентов и изменений существующих.

## Каскад и оформление

- Публичные имена `.tg-*`; SCSS внутри `@layer tds.components`.
- Токены и темы — в общих слоях; компоненты потребляют роли, не создают отдельную палитру.
- Без `!important`, ID-селекторов и JS-присваивания цветов/отступов компонентов.
- Обычный CSS приложения после подключения и утилиты TDS могут переопределять оформление.
- Размеры контролов, радиусы, шрифт, отступы и motion наследуют общие переменные.
- Локальные custom properties допустимы для измерений и документированных параметров, например координат ripple и высоты панели.

## Семантика и поведение

- Нативный HTML прежде custom widget. Без имитации кнопок через div.
- Клавиатура, видимый фокус, disabled/aria-disabled, touch ≥44px.
- Все кнопки (`.tg-btn` любого размера, `.tg-icon-btn`, `.tg-chip`, FAB, кнопки внутри полей) — одной высоты `--control-h`. Подпись не переносится: вторая строка `__subtext` помещается в ту же высоту, длинную подпись сокращают в разметке. Исключение — плитка выбора `.tg-btn--stacked`. В соединённой группе с полем все части рисуют рамку поля.
- Опциональная волна для `.tg-ripple` через `ui.js`; CSS работает самостоятельно.
- При reduced motion волна и переходы отключаются. Не анимировать всё подряд.
- Анимируются только `transform` и `opacity`, длительность — `--duration`/`--duration-fast`, кривая — `--ease`. Без анимации `width`, `inline-size`, `inset-*`.
- Недоступное состояние использует `--disabled-opacity`; собственные значения прозрачности не вводятся.
- У мелкого элемента рамка означает интерактивность: статус и обычный аватар — без рамки, фильтр, ссылка-бейдж, аватар-кнопка — с рамкой. Панели (карточка, список, таблица, уведомление) сохраняют свою рамку. Рамка всего кликабельного одна — `--action-border-color` (см. «Единые роли»). Стиль не превращает статус в кнопку: действие — это `a href` или `button`.
- Содержимое задаёт потребитель: тексты, данные, иконки, дочерние контролы и действия.
- Никаких запросов к бизнес-сервисам и скрытого хранения данных в CSS-компонентах.

## Пример и документация

Для каждого компонента нужны: назначение и границы применения, публичные классы,
минимальный пример с label/ARIA, важные состояния, обязанности приложения.
В витрине пример идёт в порядке «пример → правило (`p.example-rule`) → HTML»;
правило в одно-два предложения объясняет, когда применять и почему так выглядит.
Витрина использует общие классы, её CSS отвечает за расположение примеров.
Композиции показывают совместную работу компонентов без копирования реализации.

## Проверка

Сборка и независимый SCSS import; отсутствие новых цветов; соблюдение каскада.
Проверки поведения в Chromium/WebKit; светлая/тёмная/iOS-тёмная темы;
320px–1440px; клавиатура; disabled; reduced motion; длинный контент.
Поведение и каскад проверяются по вычисленным стилям, не только наличию классов.

## Исследование состава

Изучены официальные каталоги:

- [Carbon](https://www.carbondesignsystem.com/building-blocks/core/components/overview/components): поиск, accordion, breadcrumbs, таблицы, загрузка, формы.
- [GOV.UK](https://design-system.service.gov.uk/components/): details, summary list, fieldset, error summary, нативные формы и документированные примеры.

Для TDS выбраны поиск, раскрытие, пустое состояние, skeleton, таблица, breadcrumbs,
summary list, fieldset, error summary и range. Это дополняет уже существующие кнопки,
формы, навигацию, загрузку файлов, уведомления, modal, bottom-panel и композиции.

Сложные виджеты — listbox, combobox, календарь и диапазон дат, палитра команд, menubar —
реализованы со своими контрактами клавиатуры и состояния: CSS оформляет состояния
(`aria-selected`, `aria-activedescendant`, `aria-expanded`), а поведение примера живёт в
`docs/catalog-components.js` и показывает, что делает приложение. Tree view и
редактируемая data grid по-прежнему не выдаются за реализованные CSS-примерами.

Ядро разрешено изменять и рефакторить. Проверяется сохранение текущего внешнего
вида и публичного API, а не побайтовое совпадение исходников со старым коммитом.
Общие решения переносите в tokens/themes/base или владельца компонента; не создавайте
поздний модуль переопределений. Вариант задаёт параметры общей базы и только собственные
отличия. Порядок классов в HTML не должен заменять правила каскада.

`components/control-states` задаёт общий переход и hover. Цветовые роли состояния
задаются компонентом через `--control-idle-bg`, `--control-hover-bg`; у семейства кнопок
текст задаётся `--control-color`. Эти параметры локальны контролу, системные темы и размеры
меняют через общие токены. Наследование шрифта остаётся в base; padding, display и border
не наследуются буквально и объединяются по одинаковому назначению.

Локальные альтернативные акценты в каталоге не допускаются. Волна нажатия включается
для всех кнопок одним подключением `ui.js`; класс `.tg-ripple` не обязателен.

## Общие движки

Семейства компонентов получают геометрию и поведение из миксинов уровня компонентов;
движок не выпускает правил и слоя сам, владелец только подключает его и задаёт параметры:

- `components/floating` — поверхность и вход/выход всплывающего слоя, нижний лист на телефоне
  (меню, подсказка, hover-карточка, listbox, палитра, мега-меню, регион toast);
- `components/option` — строка-вариант 44 px (пункты меню, listbox, палитра, боковая панель,
  оглавление);
- `components/selected` — «выбрано» (мягкий акцент и рамка) и «нажато»;
- `components/steps` — маркер и соединительная линия (степпер, хронология, шаги агента);
- `components/track` — дорожка прокрутки со snap и маской краёв (карусель, колесо, лента);
- `components/field-surface` — рамка, фон и фокус поля у обёртки (поиск, группа полей,
  поле цвета).

Вариант нативного контрола, который другой компонент оформляет иначе, получает параметр у
владельца: например, `.tg-range` читает `--range-track-bg` и `--range-progress-bg`, а
ползунок оттенка только задаёт их.

## Декоративные эффекты

Эффекты необязательны и не несут смысла. Слой лежит за содержимым (`isolation` и
`z-index: -1`), поэтому контраст текста не меняется. Анимируются только `transform`,
`opacity` или зарегистрированный угол; на сенсорных экранах и при сокращённом движении
эффект неподвижен или отсутствует; у недоступного и занятого хоста эффекта нет. Цвета —
роли акцента и `--overlay-text` как нейтральный блик. Координаты указателя и программы
холста задаёт `effects.js` (`initEffects`); без модуля хост выглядит как обычный компонент.

## Единые роли (28.10.2026)

Одна роль — один источник. Компонент не заводит свой токен для того, что уже есть роль.

- **Рамка действия.** Всё, что можно нажать, обведено одной рамкой `--action-border-color`
  (`--border-action`): кнопки любых вариантов, фильтры, бейджи-ссылки, аватар-кнопки,
  радио, флажки и переключатели (`--choice-border-color` и `--switch-border-color` ссылаются
  на неё), а также бейдж внутри кликабельного элемента. Она едва заметна (.04 светлая, .02
  тёмные); при `prefers-contrast: more` становится полной.
- **Без контейнера.** Ghost-кнопки и действия внутри поля (очистка поиска, удаление тега,
  вариант колеса) — одна роль в `control-states`: без фона и рамки, при наведении меняется
  только цвет.
- **Наведение.** Всё кликабельное отвечает на наведение через `control-states`; владелец
  задаёт только параметры (`--control-idle-bg`, `--control-hover-bg`, `--control-hover-filter`).
  Контрол внутри своего `label` отвечает и на наведение подписи.
- **Соединённые части.** Кнопка, соединённая с полем или другими кнопками (`--attached`, сплит-кнопка,
  поле копирования), рисует `--group-border-color`; весь соединённый контрол имеет один край.
- **Выбранное.** «Это выбрано» — один движок `components/selected`: жёлоб и поднятый сегмент
  (сегментированный переключатель, вкладки, выпадающие списки), мягкий акцент
  (переключатель-кнопка, эмодзи), заливка, кольцо.
- **Выпадающие окна.** Меню (в том числе меню строки меню), список выбора, комбобокс и панель
  навигационного меню — один вид из `components/option`: `option.list` (плавающая поверхность,
  заливка — жёлоб на тоне страницы), `option.dropdown-row` (строка, мгновенная заливка без
  затемнения, `data-active` как наведение), `option.chosen` (выбранный, отмеченный или текущий
  пункт поднимается как сегмент). Кнопка, открывшая окно, пока оно открыто, держит вид наведения.
- **Кольцо.** Кольцо вокруг круга (бегунок ползунка, аватар в группе) берёт `--ring-bg`;
  каждая поверхность ставит туда свою заливку, поэтому кольцо совпадает с фоном под ним.
- **Шаги.** В столбце шагов текст начинается от верхнего края маркера; линия идёт через центры
  маркеров (`components/steps`: `text-at-marker-top`, `through-line`, цвет — `--step-line-color`).
- **Фокус полей.** У всех полей одна подсветка — акцентная рамка и кольцо `--focus` на
  поверхности поля (`components/field-surface`); части составного поля своего кольца не рисуют.
- **Непрозрачность.** Заливки компонентов непрозрачны. Полупрозрачны только тонкие линии
  (рамки, разделители) и затемнение `--overlay-bg` под подписью на изображении.
- **Скругление вложенных элементов.** `summary` наследует от служебного слота `details`, поэтому
  радиусы раскрывашек передаются параметрами (`--disclosure-radius-start/-end`), а не `inherit`.
- **Витрина.** Стили `docs/catalog.css` не входят в слои и перебивают систему, поэтому не
  касаются содержимого `.example-panel`.


## Каноническая всплывающая поверхность (30.10.2026)

Фон всех всплывающих поверхностей задаётся **одним** токеном `--floating-bg`
в `src/tokens/_index.scss`. Он общий для меню, listbox/combobox, навигационных
панелей, tooltip, hover-card, modal/command, toast, нижней панели, плавающей
панели инструментов и подсказок графика. Рамка, текст и тень используют
`--floating-border`, `--floating-color`, `--floating-shadow`.

Оформление принадлежит только `floating.surface`; компонент подключает миксин,
задаёт размеры, расположение и геометрический вариант. Переопределять общие роли
в компонентах запрещено. Поиск каталога использует `.tg-modal`, а не отдельную
копию оформления. `--surface-bg` остаётся ролью обычных встроенных поверхностей;
вложенная карточка не должна случайно менять фон открытого окна.

Для смены оформления приложения достаточно:

```css
:root {
  --floating-bg: var(--background-panel);
}
```

Прозрачный `.tg-bottom-panel--list` — контейнер компоновки: видимую поверхность
внутри него рисует `.tg-list`. Он не является отдельным окном.

Проверки `cascade-architecture.test.mjs` запрещают локальные определения этих
ролей; `floating-inheritance.browser.mjs` проверяет реальное наследование фона,
текста, рамки, тени и подложки колец во всех трёх темах.

Анализ сходства, приближение незначительных различий и карта владельцев:
[`style-architecture.md`](style-architecture.md). Для повторного анализа выполните
`npm run analyze:styles`. Заголовки групп используют `option.group-label`,
служебные строки панелей — `panel-parts.meta-footer`.

## Скруглённые медиаповерхности

Карточки с изображениями, слайды/миниатюры/аккордеон, обложка проигрывателя,
сравнение изображений, аватары, изображения choice-card и testimonial используют
один движок `components/media-surface`, миксин `clip`. Он объединяет изображение,
фон и затемнение в одну группу и обрезает её по существующему `border-radius`.
Обычный `overflow: clip` сглаживает слои отдельно и может давать светлую кайму.
Нельзя копировать отдельное исправление в каждый компонент.

Границей владеет медиаслой: оболочка overlay-карточки сохраняет внешние фокус и
тень. Контрол с собственной обрезкой (миниатюра) рисует фокус внутри. Скроллер
карусели не дублирует скругление слайда. У 3D-слайда собственные параметры
`--carousel-slide-clip` / `--carousel-slide-mask`: исключение для поворачиваемого
слайда не должно отключать защиту вложенной карточки.

`rounded-media.browser.mjs` проверяет пиксели краёв, реальный фокус, тень карточки
и вложенность в coverflow/fan/ring, в Chromium и WebKit при 1×/2×.


Для 3D-карусели общая обработка применяется к самому поворачиваемому `img`,
`picture` или `video`, а не к сцене. Также SVG-иллюстрациям нужен запас заливки
за границей кадра: у примеров 640×360 рабочий `viewBox="1 1 638 358"`.
Иначе сглаженные края внутренних фигур просвечивают на светлую подложку SVG
при повороте. Это отдельная причина, которую CSS-маска полностью не устраняет.
`illustration-edges.browser.mjs` проверяет реальные пять SVG при 3D-повороте,
а не только одноцветные тестовые изображения.
