# Канонические семейства и анализ итогового CSS

Требование: одно назначение — один источник оформления. Небольшие случайные
расхождения приближаем к каноническому значению. Состояния, смысловые варианты
и различия компоновки сохраняем. Компонент задаёт параметры базы, а не исправляет
её поздними стилями. `!important` не используется.

## Воспроизводимый анализ

```sh
npm run analyze:styles
```

Команда собирает CSS и снимает `getComputedStyle` на пяти страницах документации
в Chromium: 390 и 1440 px, light / dark / ios-dark. Сравниваются Git HEAD и
текущая сборка. Результаты в `artifacts/style-analysis/`:

- `report.md` — группы сходства и покрытие;
- `clusters.json` — группы по оформлению, геометрии, типографике и всем признакам;
- `before-computed.json`, `after-computed.json` — все измеренные экземпляры,
  контекст, состояние, размеры и значения свойств; сохранён SHA исходной версии.

Используется complete-link: каждый участник группы должен быть похож на каждого
другого. Порог — 16% различий, а близкие числовые значения сравниваются плавно;
разница до 2 px получает небольшой вес. Категориальные различия `display`,
`position`, `flex-direction` запрещают объединение по геометрии. Состояния
недоступности, выбора, readonly, invalid, current, expanded, busy и open разделены.
Порог — эвристика для поиска кандидатов, а не доказательство общего назначения.

Снимок не запускает сценарии примеров. Динамически создаваемые узлы, hover/focus,
псевдоэлементы и переходы проверяются отдельными браузерными тестами.
Пропущенные классы перечислены в отчёте. Для одинаковой комбинации классов
профиль использует первый экземпляр в каждом контексте; конфликтующие контексты
отмечаются отдельно, а исходные данные сохраняют все экземпляры. Нулевые размеры
скрытого элемента не означают, что у открытого компонента такой же размер.

## От групп сходства к владельцам

| Семейство | Канонический источник | Отношения и решение |
| --- | --- | --- |
| Всплывающие поверхности | `components/floating.surface`, `--floating-*` | Меню, список выбора, hover-card, modal/command, toast, toolbar, нижняя панель, tooltip и подсказка графика получают общий фон, текст, рамку и тень. Размер и размещение остаются у компонента. |
| Видимый список внутри нижней панели | `components/surfaces` + параметры родителя | Прозрачный контейнер передаёт роли всплывающей поверхности вложенному списку. Поверхность не перекрашивается поздним правилом. |
| Строки выбора и команд | `components/option` | Меню/listbox/command/nav используют общую строку; состояния выбора принадлежат `selected`. Уже существующая связь сохранена. |
| Заголовки групп | `option.group-label` | Меню, sidebar, nav-menu и command используют одни отступы, размер `--fs-xs` (12–13 px), semibold и трекинг. Небольшие прежние различия приближены к одной базе. |
| Служебные строки панелей | `panel-parts.meta-footer` | Editor status и command footer объединены. Тонкий разделитель канонически одинаковый; собственная структура содержимого сохранена. |
| Кнопки и их состояния | `buttons`, `control-states`, `selected` | Общая база уже существует. Primary/destructive, ghost, pill, disabled не превращаются в один визуальный вариант. |
| Поля и составные поля | `field-surface`, `forms` | Общие рамка, заливка и фокус уже выделены. Поиск, copy и input-group сохраняют разную компоновку. |
| Шаги | `steps` | Совпадение stepper/timeline подтверждает существующую общую базу; новая копия стилей не нужна. |
| Прозрачные обёртки, сетки, медиа и поля с похожим фоном | Разные владельцы | Сходство одного набора свойств не делает их одним компонентом. Например, у ползунка и прозрачной обёртки могут совпасть фон и текст, но контракт разный. |

## Проверки границ

`tests/cascade-architecture.test.mjs` запрещает локальное переопределение
`--floating-*`, `!important` в компонентах и отдельное оформление поиска каталога.
Также проверяет использование общей базы заголовков и служебных строк.

`tests/floating-inheritance.browser.mjs` меняет роли на корне и проверяет
фактические стили 13 видов всплывающих поверхностей, вложенный список нижней
панели и одинаковые заголовки групп во всех трёх темах.

Эталон прежнего каталога не перезаписывается. Тест сравнения явно учитывает
согласованные изменения: единый фон меню, канонический заголовок группы и переход
поиска каталога на публичный `.tg-modal`.
