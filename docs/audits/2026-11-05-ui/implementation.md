# Реализация изменений по аудиту TDS

Все восемь предложений F01–F08 реализованы в рабочем каталоге. Библиотека собрана
из SCSS, `dist` обновлён, публичные примеры и классы сохранены. Коммит и публикация
не выполнялись. Исходный [отчёт аудита](report.md) остаётся снимком до изменений.

| Пункт | Изменение |
| --- | --- |
| F01 | Промежуточные `li` результатов поиска имеют `role=none`; option принадлежит listbox в accessibility tree. |
| F02 | Общий `media-surface.caption` применён к подписям carousel, image accordion и compare. Белый текст получает существующую overlay-подложку; формулы палитры не менялись. |
| F03 | Публичный `.tg-action-slot` резервирует место под цель `--control-h` в переносимых группах. Бейдж сохраняет видимую высоту; соседняя строка больше не перекрывает расширенную цель. |
| F04 | Названия четырёх action badges включают видимое «12» и действие. Декоративный знак бренда и инициалы кнопки-аватара скрыты от accessibility tree; существующие корректные имена сохранены. |
| F05 | Публичная `.tg-scroll-region` и общий `initScrollRegions` оставляют Tab-stop только при переполнении. Обработаны изменение размеров, текста, дочернего содержимого и cleanup. Стрелки работают на самой области и в WebKit; вложенные контролы сохраняют собственную клавиатуру. |
| F06 | Все 24 слайда используют div с именованной ролью group и вложенный нативный figure. Сохранены 20 существующих figcaption и геометрия всех вариантов; старый CSS-контракт прямых изображений продолжает работать. |
| F07 | Каталог и три standalone-примера подключают `.min.css`. Необязательные эффекты и canvas инициализируются при приближении соответствующего раздела или первом взаимодействии. Поиск, навигация, формы и HTML доступны сразу. |
| F08 | Миниатюры получили intrinsic width/height. |

Документация публичных вариантов находится в README; DESIGN и стандарт компонента
обновлены ссылками и общими правилами. Карта потребителей цвета перегенерирована.
Обнаруженное противоречие README о рамке/тени информационного бейджа устранено.
Ручная установка по-прежнему требует только `ui.js` и `effects.js`: новый исходный
модуль прокрутки включается сборкой внутрь `ui.js`.

## Повторный аудит доступности

В девяти конфигурациях axe (три темы × три ширины), а также в открытом поиске
больше нет aria-required-children/parent, listitem, aria-allowed-role,
scrollable-region-focusable и новых дублирующихся landmarks.

Остаются четыре `label-content-name-mismatch` на бренде, инициалах аватара,
подписанном picker и ссылке «Счета, 12 новых». Это те отдельные случаи, которые
исходный отчёт исключил из автоматических массовых исправлений: декоративные
символы и корректные составные доступные имена. Они не объявлены сертификатом
соответствия; реальная проверка VoiceOver и голосового управления не выполнялась.

Контраст подписей дополнительно измерен по пикселям в обоих движках и трёх темах:
медиана фона в прямоугольнике подписи около 11,5–11,7:1. Прозрачные скруглённые углы
не входят в штрихи текста, поэтому минимум всего прямоугольника не используется
как контраст букв. Регрессионный тест отдельно проверяет роль на белом фоне ≥4,5:1.

## Производительность

В окончательной версии каждый основной CSS-запрос уменьшился с 265004 до 215417
байт передачи локального сервера (примерно на 18,7%). Это относится и к встроенной
сцене: она больше не загружает несжатую копию библиотеки.

Три исходных Lighthouse mobile прогона дали 71/71/72. Три окончательных — 65/72/73;
медиана 71 → 72, LCP 4,69 → 4,54 с. Первый окончательный прогон был медленнее
(LCP 7,02 с). Медиана TBT выросла с 17,5 до 89,5 ms; CLS остался около 0,003.
Параллельные проверки создавали разную нагрузку CPU, поэтому это лабораторные
наблюдения, а не доказательство устойчивого ускорения production.

Доставка минифицированного CSS и откладывание необязательных эффектов реализованы;
следующий шаг измерений — контролируемый production baseline, серверное сжатие
и кэширование реального хостинга. Его конфигурации в проекте нет; локальный
сервер намеренно сохраняет `no-store`. Примеры и CSS-компоненты не удалялись ради score.

## Существующие сбои полного браузерного набора

Полный `npm run test:browser` запускался в обоих движках и остановился на
`progress-stripes`. После этого все оставшиеся 44 файла на движок были запущены
отдельно с сохранением результатов. В полном охвате найдены сбои в девяти файлах:

| Файл | Движки | Причина остановки |
| --- | --- | --- |
| progress-stripes.browser.mjs | Chromium, WebKit | Порог видимости полос не достигается в dark: около 17,03 и 15,89 вместо 20. |
| button-spacing.browser.mjs | Chromium, WebKit | Старое ожидание отступа при узкой текстовой кнопке. |
| baseline-compatibility.browser.mjs | Chromium, WebKit | Сохранённая историческая fixture расходится с текущими цветовыми сериализациями и стилями. |
| browser.mjs | Chromium, WebKit | Неоднозначный locator переключателя «Уведомления» находит два примера. |
| components-wave-0.browser.mjs | Chromium, WebKit | Устаревшее ожидание тени выбранного сегмента / сбой клавиатурного шага. |
| patterns.browser.mjs | WebKit | Тест ждёт упрощённую строку clip-path, движок сохраняет calc/clamp. |
| components-wave-1.browser.mjs | WebKit | Ожидание состояния focus-visible в сценарии группы кнопок. |
| components-wave-2.browser.mjs | WebKit | Таймаут ожидания focus-visible у карточки выбора после клавиатурного шага. |
| components-wave-3.browser.mjs | WebKit | Ожидание перехода Tab внутрь навигационной панели. |

Каждый из этих файлов дополнительно запущен на отдельной копии исходного `HEAD`
с исходными CSS, HTML и runtime — сбои воспроизводятся там тоже. Для baseline
изменены только порты тестовых серверов, чтобы они не пересекались с рабочими.
Сбой WebKit patterns также подтверждён отдельно на Node 26, как и основной набор.
Эти файлы не подгонялись под текущую задачу. Следовательно, весь браузерный набор
не объявляется зелёным, хотя целевые проверки изменений прошли.
