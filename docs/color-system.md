# TDS: единые формулы цветов

Этот документ — основной контракт цветов. Реализация операторов:
`src/tokens/_color-formulas.scss`; коэффициенты и роли: `src/tokens/_index.scss`.
Темы: `src/themes/_index.scss`. Полная карта потребителей: `color-consumers.json`.

## 1. Входные данные и запреты

У темы четыре входных цвета: фон B, текст T, акцент A, опасное действие D.
Дополнительно тема задаёт color-scheme и коэффициент инверсии i:
**−1 для светлой, +1 для обеих тёмных**. Чёрный и белый — постоянные границы
цветового пространства, а не дополнительные настраиваемые палитры.

Компонент выбирает семантическую роль. Он не задаёт RGB, свою смесь, формулу
или отдельный цвет для темы. Имена совместимости — ссылки на существующие роли.
Исключений для «красивого конкретного компонента» нет.

Формулы едины, но тип операции определяется смыслом роли: текст нельзя считать
фоном, а поднятую панель — состоянием наведения. Коэффициенты не меняются между
темами; тема меняет только входные цвета и i.

## 2. Операторы

### TONE — инверсия светового шага

В OKLCH, где L ∈ [0,1]:

`TONE(X, d, i) = OKLCH(clamp(0, L(X) + i × d, 1), C(X), h(X))`

Цветность C и тон h исходного цвета сохраняются до отображения в доступном
цветовом охвате. При выходе из охвата браузер отображает доступный цвет;
поэтому проверяются и вычисленные OKLCH, и итоговые пиксели sRGB.

| Роль | Основа X | Шаг d | Результат |
|---|---|---|---|
| Приглушённая поверхность | Панель P | .065975 | M = TONE(P, .065975, i) |
| Дорожка выключенного switch | M | 0 | Та же M, без собственной формулы |
| Поля, вторичные кнопки, фон сегментов, выбранные строки | M | 0 | Общая роль M |
| Hover | Роль фона конкретного контрола X | .023861 | TONE(X, .023861, i) |
| Ghost/no-hover | X | 0 | Исходный фон X; текстовый отклик ghost сохраняется |

Шаг .065975 получен из светлого образца `L(#fff) − L(#e9e9e9)`.
Шаг .023861 — из `L(#fff) − L(#f7f7f7)`.
Это не коэффициенты WCAG contrast ratio: они описывают воспринимаемую светлоту.
Смена яркости всего элемента запрещена: текст, бегунок, иконки и вложенные бейджи
не должны осветляться или затемняться вместе с фоном. Параметр совместимости
`--control-hover-brightness` равен 1.

### PANEL — поднятая поверхность

`P = OKLCH(clamp(.215, L(B) + .06, 1), C(B), h(B))`

Это направление возвышения, поэтому i здесь не применяется: панель должна
отделяться от страницы и в светлой, и в тёмной теме. Общий нижний предел .215
не даёт панели слиться с чёрным iOS-фоном. Светлый фон у верхней границы
даёт белую панель. Нет отдельного RGB панели Desktop и отдельного процента iOS.

### MIX — семантическое смешивание

`MIX(X, w, Y) = color-mix(in srgb, X w, Y)`

| Роль | Формула |
|---|---|
| Основной текст | T |
| Вторичный текст | MIX(T, 70%, P) |
| Приглушённый текст | MIX(T, 55%, P) |
| Основной акцент | A |
| Акцентная заливка | MIX(A, 72%, black) |
| Мягкий акцент | MIX(A, 12%, P) |
| Читаемый акцент, light | MIX(A, 72%, black) |
| Читаемый акцент, dark | MIX(A, 55%, white) |
| Опасная заливка | MIX(D, 72%, black) |
| Мягкая опасная заливка | MIX(D, 10%, P) |
| Читаемый опасный текст | Та же формула читаемого акцента, с D вместо A |

Вес читаемого тёмного foreground задаёт общий параметр
`--semantic-readable-dark-weight: 55%`. Он проверен на всех нейтральных
поверхностях и тестовых тёмных акцентах; прежние 65% давали около 3.92:1
на нейтральном контроле для тестового фиолетового акцента.

Для текста и семантических заливок применяется MIX, а не автоматический перенос
TONE: здесь требуется читаемый foreground на собственной поверхности.
Разница light/dark читаемого foreground — общая семантическая роль в токенах,
не условие внутри компонентов. Цвета исходного акцента и danger не инвертируются.

### ALPHA — прозрачность

`ALPHA(X, a) = RGB(X.r, X.g, X.b, alpha=a)`

| Роль | X | a |
|---|---|---|
| Граница панели/поля | T | .08 |
| Тонкая граница/действие | T | .04 |
| Граница при наведении панели | T | .24 |
| Усиленная граница | T | .50 |
| Затемнение за оверлеем | black | .66 |
| Тень контрола | black | .12 |
| Тень плавающей поверхности | black | .20 |
| Светлая/тёмная волна нажатия | white / black | .25 |
| Нативная стрелка select | black в light / white в dark | .65; hover: 1 |

При повышенном контрасте роли границ ссылаются на усиленную границу.
Disabled — общая прозрачность .5 всего контрола, а не ещё один набор оттенков.

## 3. Выбор ролей компонентами

- Карточки, модальные окна, меню, listbox, панели: P.
- Поля, поиск, составные поля, фон tabs/segmented, вторичные кнопки, статусы:
  M, полученная одной TONE-формулой от P.
- Выключенный switch: M; включённый: A; бегунок: white. Геометрия не меняется.
- Основное действие: акцентная заливка; опасное действие: опасная заливка;
  надписи на насыщенных действиях: white.
- Акцентный бейдж: мягкий акцент + акцентная надпись в light;
  насыщенный акцент + основной текст в dark. Вся пара определена в токенах.
- Выбранная строка: роль M; выбранный сегмент: P. Это назначение роли,
  а не самостоятельный цвет. Имена ARIA, маркер и геометрия сохраняют смысл выбора.
- Индикаторы прогресса: читаемый акцент на M, чтобы значение отличалось от дорожки даже при тёмном пользовательском акценте.
- Состояния hover/disabled/focus: общие движки, значения из общих ролей.
- Все старые публичные псевдонимы ссылаются на эти же роли.

Точный список файлов, свойств, ссылок на роли и значений генерируется командой
`node scripts/audit-colors.mjs --write`. Он учитывает параметры цвета разделительных колец с суффиксом `-ring`
(не геометрические `--ring-size` или `--ring-width`). Он охватывает каждый компонентный SCSS, base и utilities,
а не только перечисленные здесь примеры.

## 4. Цвета, которые не являются оформлением темы

Маска использует непрозрачный `--mask-opaque`: её RGB не отображается как цвет UI.
Цветовой picker показывает настоящие оси HSV: чёрный, белый и выбранный hue;
формулы SPECTRUM и HUE-SPECTRUM определены в том же модуле.
HUE-SPECTRUM проходит через HSL(h, 100%, 50%) при h = 0°, 60°, 120°,
180°, 240°, 300°, 360°; это стандартная шкала оттенков, не цветовые роли темы. Кольцо picker использует постоянную
пару black/white для различимости на любом выбранном цвете. Его нельзя заменить
акцентом темы, иначе инструмент покажет неправильный цвет.

Нативная стрелка select — SVG-адаптер: фоновые SVG не наследуют currentColor,
поэтому оператор SELECT-ARROW генерирует два нейтральных изображения с одной
прозрачностью .65 (при hover — 1). Маски и ручки имеют отдельные технические роли,
а не произвольные новые оттенки.

Градиенты декоративных компонентов интерполируют готовые роли; их пространственные
позиции принадлежат компоненту, а новые исходные оттенки в них не вводятся.

`transparent`, `currentColor` и системные цвета forced-colors сохраняют своё
нативное значение. Изображения, видео и выбранные пользователем цвета — данные,
а не дополнительные палитры интерфейса.

## 5. Проверки и изменение контракта

1. Изменять формулу или коэффициент только у общего владельца.
2. Запустить `npm run check:colors`: никаких локальных цветов, формул или
   переопределений производных ролей в темах.
3. Перегенерировать `docs/color-consumers.json`; проверить новых потребителей.
4. `npm test` и `npm run test:colors`: формулы, алиасы, hover, палитры,
   читаемость, границы, поля и эффекты во всех трёх темах в Chromium/WebKit.
5. Проверить TONE: знак и величину ΔL, неизменность C/h до gamut mapping;
   проверить PANEL: формулу и нижний предел; проверить алиасы общих ролей.
6. Проверить реальные составные поля, кнопки, бейджи, списки, tabs и switch,
   выбранные/disabled/hover/focus состояния, контраст текста и границ.
7. Посмотреть скриншоты всех тем. Формульный тест не заменяет визуальную проверку.
8. Менять эту документацию вместе с формулой; не сохранять рядом старую формулу
   как ещё один способ оформления того же элемента.

Для произвольных пользовательских исходных палитр читаемость не следует
автоматически из этих коэффициентов: пользовательский набор проходит ту же
проверку, что и три штатные темы. Не объявлять проверенными неизмеренные цвета.
